## How it works (max ~10 lines)
Server paginates (page + per_page clamped to 50), filters/search run on the whole set before the cut, frontend resets to page 1 when a filter/search changes and ignores stale answers (request counter). Opt-in endpoints (coordinator interns, dean interns, inquiries, support, tasks view, message limit) keep returning the full list when no page/view/limit is sent, so dashboards, the pending/roster readers and exports are unchanged. Task Active board is returned whole (open work); only History is paged. Feed-like lists use LoadMore, tables use Pagination. Left unpaged on purpose: companies, supervisors, superadmin schools, AI usage, revenue breakdown, supervisor interns, supervisor/intern evaluations, intern documents/evaluations, coordinator support tickets and Dean feedback (capped 100), dean intern detail tabs (capped 31/40/60), bell (30).
