## How it works (max ~10 lines)
Inquiry -> superadmin convertInquiryToSchool creates school + subscription offer (offer_expires_at). The school's Dean (not the coordinator any more) acceptOffer, then pays via PayMongo checkout (checkout creates session, verifyCheckout confirms) or uploads manual proof (uploadProof) which superadmin verifies/confirms. Expired active subs are detected lazily (rejectIfExpired). Upgrades: upgradeQuote prorates, requestUpgrade starts a pending payment while the current plan stays active, cancelPendingUpgrade aborts; a confirmed one supersedes others (supersedeOtherActive). Other changes go through requestPlanChange -> superadmin approve/reject. Feature gating is label membership in plan.features via PlanFeatures::has (only Premium-exclusive labels gated; Basic and Premium share the rest). Suspension via toggleSchoolSuspension.

Approval (approvePlanChange): non-upgrade (amount <= running amount AND list price <= running list price) -> scheduled row. Otherwise creates an `accepted` row (no dates, no paid flag, no txn; the old plan stays active; expired old row -> `expired`, school status `accepted`), cancels older accepted/scheduled rows, notifies Dean. School::approvedChange() (accepted row newer than active) -> `approved_change` in the Dean session payload; Dean pays via normal checkout/verify-checkout/proof; activation supersedes the old row. A 0 amount: checkout 422; Super Admin confirmSchoolPayment activates and records a paid 0 txn with method `waived`. SuperadminFullController::schools returns `awaiting_payment_change`; planChangeRequests returns `awaiting_payment`.
Monthly -> yearly same plan (requestUpgrade/upgradeQuote via isPeriodUpgrade): pending_payment row, no dates, list_price=yearly, discount_amount=credit, amount=net, agreement_note starts with SubscriptionBreakdown::PERIOD_UPGRADE_NOTE (marker). credit = paid amount * remaining/total days. SubscriptionBreakdown::forPeriodUpgrade/isPeriodUpgrade/periodShape; forPendingUpgrade falls back to forSubscription when marker or no upgrade txn. Yearly -> monthly stays scheduled.
Caveats: switchPlan/approvePlanChange used to create a `paid` row with NO payment_transaction (PMFTCI case); fixed. isRenewalExpired is true from the start of end_date. No renewal flow exists besides scheduled hand-over.
