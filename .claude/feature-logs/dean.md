## How it works
- One Dean + one coordinator per school. Dean pays/edits settings, invites/deactivates the coordinator (see Phase 1 rules in git history/code), and monitors read-only.
- Intern flags (internRows): no_clock_in = active, started, >=3 completed working days (Mon-Fri, excluding today) since last clock-in (or start date); behind_hours = active, time-elapsed% >= 15 and hours% < elapsed% - 20; missing_documents = narrative document sections missing and (completed or elapsed >= 50%); evaluation_due = active, no evaluation, end date within 14 days or passed.
- Alerts (overview): stale documents (pending > 3 days), no_clock_in count, behind_hours count, active interns without supervisor, evaluation_due count, invitations unanswered >= 7 days (blue), coordinator quiet >= 3 days / never active / invite pending >= 3 days or expired / no coordinator, subscription not active or ends within 14 days (red <= 3). Empty = "All clear".
- Pending work items sorted oldest first; stale = age > 3 days. Last active = max(last_login_at, token last_used_at, latest activity log). Activity timeline = activity_logs where user_id = current coordinator and school_id = school (module filter, 20/page).
- Feedback: POST requires an ACTIVE coordinator (422 if none/pending); creates dean_feedback, NotificationService::toUser coordinator type `dean_feedback` link /coordinator/feedback, activity log "Sent feedback to coordinator". (Threads/replies: see above.)
- Activity records ADDED for coordinator actions (ActivityLogService): Updated partner company, Updated supervisor, Added evaluation criterion, Commented on a task / subtask, Updated narrative report template, Changed/Removed report logo (module Reports). Already recorded before: document upload/review, add/delete company+supervisor, invite/import/delete/status/deployment/reassign intern, resend/corrected invitation.
- STATUS GROUPS (InternMonitoringService): completed = status completed or hours met; at_risk = projected finish after end date OR no clock-in 5+ working days OR 2+ flags; needs_attention = 1 flag; on_track = none; inactive excluded from counts. Elapsed% / "behind" use working days (Mon-Fri, holidays not excluded). Projection: pace = approved hours / working days over last 21 days (fallback whole deployment), needs >=2 attendance days, finish = Nth working day after today. Calendar codes P/M/X/A/O/F from Monday 3 weeks back (28 days).
- Scorecard verdicts: review time (<=2d good, <=5 watch), stale backlog >3d (0 good, 1-3 watch), supervisor% (>=95/80), evaluated% (>=80/50), invitations accepted% (>=80/50). reviewed_at set in CoordinatorMonitoringController::reviewDocument; older rows estimated from updated_at.
- Feedback threads: open -> acknowledged (coordinator ack or reply) -> resolved (dean); dean can reopen; coordinator cannot reply when resolved (422). Notification types dean_feedback (to coordinator), dean_feedback_reply / dean_feedback_ack (to dean).
- Weekly email: recipients = active dean, pref on, not bounced, school not suspended, active subscription. Railway has NO scheduler service yet (queue runs queue:work only), so a service running `php artisan schedule:work` is needed.
- List endpoint uses fixed queries (no per-intern queries); tests assert < 30 queries and the same count for 3 vs 15 interns.
