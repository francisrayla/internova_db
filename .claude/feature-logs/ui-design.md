## How it works (token layers)
1. `--ui-*` tokens (light on `:root`, dark on `.dark`, class set on <html> by useTheme) feed plain-CSS components.
2. `@theme` retunes Tailwind's colours/radius/shadow, so existing utilities (`text-slate-500`, `bg-blue-50`, `rounded-2xl`) are already calm in light without touching screens. Shadows are inlined by Tailwind, so dark kills them with `.dark .shadow-sm { --tw-shadow: ... }`.
3. `.dark .bg-white { var(--ui-surface) } ...` repaint the same utilities in the blue dark family (ground #0d1424, surface #141c2e, raised #1a2438, line #26324a, ink #e6ebf5, muted #9aa8c0, accent #6a9bf0). Solid `bg-blue-600` becomes #2c64c8 (white text 5.6:1).
4. Kit CSS is in `@layer components` and both kit files declare `@layer theme, base, components, utilities;` first, so Tailwind utilities still win over kit classes whatever order CSS loads in. Unlayered rules (globals.css overrides, `.sheet-*`) beat both.
5. Gotcha: single-session login. Running two scripts that log in as the same demo user at once logs the first one out (screenshots show /login). Run one script per role.
