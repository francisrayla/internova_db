## How it works
Supervisor creates a task for one or many interns (deployment_ids; group needs leader_id; not-started and pending_activation interns refused) -> task_assignees. Intern moves status (updateTask, only when no subtasks), adds/completes subtasks (plan-gated), uploads proof, completes the task (leader only for groups). Subtask status changes two ways, same API (PATCH /intern/subtasks/{id}, or POST .../complete for Done + proof): drag, or the dropdown in SubtaskBoard.StatusDropdown.
Rules (2026-10-08): a parent is only done when every subtask is done (completeTask check + Task::setStatus guard; UI shows a disabled "Mark task complete" + "Finish all subtasks first (n/m done)"). A done task is closed to new subtasks (Task::subtaskAddBlock, 422 both roles) and its subtasks cannot be moved back (updateSubtask 422); finishing a subtask or removing an unfinished one still works (repairs old bad data). Rated task: no edit, no reopen (intern updateTask 422), finished subtasks not removable. Cannot rate while a subtask is open.
Active vs History: a done task waits in Active until rated; backend sends awaiting_rating (done + no rating + plan has TASK_RATINGS; on Basic nothing can rate it so it goes to History at once); all 3 roles use taskState.js. Supervisor edit: PATCH /supervisor/tasks/{id} (title, description, priority, due_date), until rated; notifies assignees (type task_updated, link /intern/tasks/{id}) + ActivityLog "Edited task". Due badge = Manila calendar days (Due today / tomorrow / in N days / Overdue by N).
