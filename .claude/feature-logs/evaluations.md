## How it works
Each school is seeded with the default rubric; coordinator can add criteria. Rules: (1) an evaluation can only be CREATED once the intern's deployment isFinished() (completed, or approved hours >= required_hours, same rule that closes attendance); (2) one evaluation per deployment: a second create is refused with code already_evaluated (UI offers Edit); (3) the supervisor (any supervisor of the company) can EDIT any evaluation at any time (no hours/count rule on edit, so old rows stay fixable); coordinators and interns are read-only. Create = Evaluation + EvaluationScores, overall weighted by criterion weight; scores above max_score are refused. Technical Ability suggestions come from task-rating average; they are suggestions only, any value 0..max is accepted (create and edit). There is ONE evaluation per intern, no Prelim/Midterm/Final: evaluation_type is not written, not validated (an old client sending it is ignored) and not exposed; formal vs manual = has scores or not. Old rows keep their raw value in the DB only. Old data with 2+ evaluations per intern stays readable; the OFFICIAL one (score on dashboards, narrative report) is the latest by evaluation_date then id (the most recent assessment wins; the old term name plays no part). No automatic deletion.
